# Phone checks for FirmPulse 1.0.0

Record real device results before making claims about model coverage or physical performance. The delivered release is signed; automated tests are separate from these physical-phone checks.

1. On a clean Samsung installation, verify that only this phone's model is prefilled and no fixture firmware result appears. Confirm CSC is empty until entered. On other phones the selection should be clean. Restart after a manual selection and confirm it is retained.
2. Check the phone's light/dark setting and both manual theme options. Test large fonts, keyboard appearance, rotation, gesture/button navigation and display cutouts.
3. Enter full model endings including B/U/U1/N, use dropdowns and type CSC manually. Different variants must stay distinct.
4. Check an S-series model. Confirm the support notice remains visible on Home and in Tools. Compare full released and test details, not short suffixes alone. Keep the JSON report for any mismatch.
5. Review an older test or beta entry. Confirm the age warning is qualified by published dates or build-code clues. Hidden names, unavailable reference data and different same-month branches must not acquire fabricated dates.
6. Compare released dates, Android version, patch and notes with the linked Samsung source. A failed notes request should not invalidate successful firmware feeds. Known released names must not become a test headline.
7. Try offline and unavailable pairs. Confirm clear errors, preserved successful baselines, cancellation and responsive controls.
8. Check rapid tab changes, long Tools lists, paging, glass toggles and reduced motion. Observe animation feel/frame rate on the actual Samsung phone; simulated screenshots cannot establish this.
9. Save/remove devices, opt into watchlist alerts, allow notifications and inspect behavior under battery saving and after reboot. Android may defer periodic checks.
10. Export/import saved devices, JSON/CSV and shared cards. Verify developer links and the Star FirmPulse link. Confirm no private signing data is in public assets.

For updates from a development APK, export saved devices, uninstall that differently signed app, install 1.0.0 and import. For subsequent permanent-key releases, validate an in-place update preserving saved data.
